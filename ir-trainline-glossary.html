IR Trainline Glossary

This glossary explains the domain concepts used in the IRCTC booking flow and the formal model.

  • Search: User browses trains, dates, classes, quotas.
  • Idle: Initial state before a search begins.
  • Select: User chooses a specific train and class.
  • DetailsEntered: Passenger names, ages, etc.
  • Reviewing: User sees fare summary and journey details.
  • On-Hold: Temporary seat lock before payment; 5-minute grace timer.
  • Stateless application servers: Application instances keep no booking-session state locally, so requests can safely move between servers.
  • JWT at edge: The edge validates the signed JSON Web Token before allowing a request into the booking platform.
  • ttl (Sliding TTL Window): A 300-second session window refreshed on each user action.
  • Regulated token ingress: The controlled entry point that accepts only edge-validated tokens and applies platform access rules.
  • Redis + Lua atomic TTL extension: Redis stores transient booking state while a Lua script updates the state and extends its TTL as one atomic operation.
  • holdTimer (On-Hold grace timer): The 300-second countdown that protects the temporary seat lock before payment.
  • Paying: User is at external payment gateway (mocked).
  • Confirmed: Booking finalized after successful payment handling.
  • Expired: On-Hold timed out or payment failed; seat released.
